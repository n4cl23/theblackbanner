# ADR 0013 — Generic versioned editorial CMS

- Status: accepted
- Date: 2026-07-18
- Requested equivalent: `0006-cms` (not used because ADR 0006 already exists)

## Decision

Persist the validated common editorial core in `ContentEntity`, discriminated by content type and locale. Store flexible feature payloads as validated JSON while workflow, slug, locale, version, publication, translation, and media references remain relational fields.

Every create, edit, transition, duplicate, archive, publish, and restore operation runs server-side, checks role capability, applies optimistic concurrency through `version`, writes a revision snapshot, and creates a sanitized audit entry.

Media records store only provider metadata and storage keys. Large bytes are rejected until a storage adapter is configured.

## Consequences

The CMS supplies a shared workflow without duplicating tables prematurely. Feature-specific relational projections can be added after real editorial usage identifies stable query needs.
